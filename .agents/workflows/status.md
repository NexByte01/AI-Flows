# 仓库状态审计

> 适用场景：
> - "分析当前项目进度"
> - "我们现在到哪了？"
> - "有什么风险或缺口？"
> - "下一步该做什么？"

## 工作原则

- 先看**实际本地状态**，再得出结论 — 不凭记忆总结
- 优先检查区域：当前分支、未提交变更、记忆文件、活跃项目状态
- Git 操作：允许读取状态，不自动执行 commit、split、push 或 merge
- 远端信息使用可用的 GitHub 集成；不可用时注明"结论仅基于本地状态"

## Token 控制

- 默认只读 3 个项目恢复文件：`README.md`、`MEMORY.md`、`memory/tasks.md`。
- 日志、架构和输出目录只在任务需要时按关键词或目标路径读取。
- 输出摘要不复制长任务列表，只列 3-5 个最关键下一步。
- 若需要恢复最近一次具体工作，只读取当天 `memory/YYYY-MM-DD.md`；不要默认读取历史日志。
- 若当前任务涉及架构，再读取 `docs/ARCHITECTURE.md` 的相关章节。

## 建议检查顺序

### 1. 本地仓库状态

```bash
git branch --show-current
git status --short
git log --oneline -5
```

### 2. 远端与协作状态

```bash
git remote -v
```

如果 GitHub 集成可用：检查未合并的 PR 和 Issue 状态。

### 3. 项目健康度

检查 `projects/registry.yml`：
- `current_project` 是否已设置？
- 所有 `building` 状态的项目是否有有效的记忆文件？
- 是否有不在 registry 中的孤儿目录？

### 4. 代码与内容完整性

优先目录：`.agents/`、`projects/`、`memory/`、`.github/workflows/`

## 输出格式

### 1. 当前阶段评估

一段话描述项目当前阶段。

### 2. 状态摘要

| 项目 | 状态 |
|------|------|
| 当前分支 | `develop` / `feature/*` / `main` |
| 未提交变更 | X 个文件 |
| 近期工作聚焦 | 例如"工作流重构 / 模板升级" |
| 远端状态 | 已配置 / 未配置 |
| 记忆文件 | 已更新 / 需要更新 |

### 3. 关键问题

按严重程度列出阻塞项、风险和缺口。

### 4. 下一步建议

3-5 条优先级排序的可执行建议。

## 补充规则

- 如果用户问"项目进度"：聚焦**阶段、风险、下一步**
- 如果用户问"仓库状态"：聚焦**分支、未提交变更、近期提交**
- 如果用户问"能发布吗"：聚焦**工作流、自动化、配置完整性**
