# 记忆治理

本目录保存项目本地记忆。它的目标是减少重复解释、保留长期决策，同时避免记忆无限膨胀和旧事实误导后续执行。

## 文件分层

| 文件 | 用途 | 默认读取 |
| --- | --- | --- |
| `../MEMORY.md` | 长期规则、稳定决策、关键路径 | 是 |
| `tasks.md` | 当前待办、已完成事项、短中期任务状态 | 是 |
| `YYYY-MM-DD.md` | 当天工作日志、临时决策、过程记录 | 否，按需 |
| `archive/` | 阶段归档、旧完成项、历史摘要 | 搜索命中后读取 |
| `../projects/<slug>/MEMORY.md` | 单个项目的长期目标、边界和约定 | 当前项目时读取 |
| `../projects/<slug>/memory/tasks.md` | 单个项目的任务状态 | 当前项目时读取 |
| `../projects/<slug>/memory/YYYY-MM-DD.md` | 单个项目当天过程记录 | 按需 |
| `../projects/<slug>/memory/archive/` | 项目阶段归档 | 搜索命中后读取 |
| `../projects/<slug>/memory/reviews/` | 代码/架构审查报告 | 按需 |

## 能进入长期记忆的内容

- 项目定位、边界、长期约定。
- 当前主项目和项目目录规则。
- 已明确的架构决策和不能反复争论的取舍。
- 外部仓库路径、线上地址、重要文档路径，但必须标注验证日期。
- 反复踩坑后形成的工作规则。

## 不应进入长期记忆的内容

- 一次性命令输出。
- 临时讨论过程。
- 可从文件直接读取的长篇内容。
- 已完成但无长期价值的细节。
- 未验证的猜测。
- 易变化的价格、版本、部署状态、仓库 dirty 状态。

这些内容应放入当天日志或任务文件；需要时通过搜索定位。

## 易过时事实

以下事实不能只依赖记忆，执行前必须重新验证：

- 当前线上部署状态。
- Git 工作区状态。
- 依赖版本、模型能力、API 可用性。
- 价格、套餐、平台规则。
- 外部仓库路径是否仍存在。
- `.env`、CI/CD、云服务等环境配置状态。

推荐写法：

```text
- 源码路径：`D:/Projects/MyApp`，last_verified: 2026-05-13。
```

如果验证日期距离当前任务较远，先检查文件系统或平台状态，再继续。

## 读取策略

默认读取顺序和按需加载规则见 `AGENTS.md`「默认读取策略」章节。日志文件 `YYYY-MM-DD.md` 仅在追溯历史决策时读取。

## Token 控制

- 默认恢复上下文只读：`AGENTS.md`、根级 `MEMORY.md`、`projects/registry.yml`、当前项目 `MEMORY.md`、当前项目 `memory/tasks.md`。
- `YYYY-MM-DD.md` 只读当天文件或命中的少量历史文件；不要默认读取全部日志。
- `docs/ARCHITECTURE.md` 只在架构相关任务中读取。
- 长参考资料只保留链接或摘要进入记忆，执行时按需打开。

## 维护节奏

- **每日收尾**：只追加当天日志和任务状态，不做大规模整理。
- **每周维护**：执行 `/memory-maintenance`，清理过时信息、归档已完成任务。
- **架构变更后**：立即执行 `/closeout` 和必要的 `/update-architecture`。
- **阶段结束后**：做阶段归档，压缩 `tasks.md` 的已完成区。

### 归档规则

- `tasks.md` 保留"下一步""暂不做"和最近 10-20 条高价值已完成项。
- 旧完成项按阶段写入 `archive/YYYY-MM-<phase>.md`。
- 归档文件顶部写明覆盖范围、归档日期和是否仍需重新验证。
- 如果 `MEMORY.md` 超过 150 行，应合并重复内容，把过程细节移到日志。
- 不删除历史日志，除非用户明确要求并确认范围。
