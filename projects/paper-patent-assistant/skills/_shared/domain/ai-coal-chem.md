# 交叉学科知识基座：AI × CS × 煤化工

本知识基座旨在为所有后续的文献阅读、论文写作、盲审评估和专利生成技能提供**领域专属的强制性上下文**。

## 1. 概念防混淆协议 (Concept Disambiguation)

在处理跨学科文本时，极易发生“语境错位”。必须强制遵守以下映射与替换规则：

| 错误/模糊表述 (Bad) | 规范表述 (Good) | 原因分析 |
| :--- | :--- | :--- |
| 模型发现了化学反应规律 | 模型预测的动力学参数与实验/机理模型高度吻合 | 算法本身不能“发现”物理化学定律，只能拟合和预测。必须尊重化工机理的主导地位。 |
| 神经网络的节点表示煤炭 | GNN 的节点（Nodes）映射煤炭分子结构的官能团，边（Edges）映射化学键 | 必须将抽象的图拓扑结构明确具象化为实际的煤化学微观或宏观结构。 |
| 模型输出煤气化结果 | 模型输出煤气化过程的关键指标（如合成气产率、碳转化率）的预测值 | “输出结果”过于宽泛，需指代具体的化工评价指标。 |
| 优化了反应堆温度 | 生成温度控制曲线并反馈至气化炉控制单元 | 算法本身不能改变温度，必须通过控制系统实施，这对专利确权至关重要。 |

## 2. 论文盲审红线 (Reviewer Red Lines)

当执行 `nature-reviewer` 进行盲审时，三位评审专家必须携带以下**交叉领域专属视角**：

*   **物理意义红线 (Reviewer 1 - 煤化工专家)**：
    *   **排查重点**：模型的输入特征（Features）是否具有明确的化工物理化学意义？如果全是不可解释的数学变换（如单纯的 PCA 主成分），必须提出“缺乏可解释性”的重大批评。
    *   **基线要求**：对比 Baseline 不能仅仅是其他 AI 模型（如把 LSTM 换成 Transformer），必须与传统的热力学模型或 Aspen Plus 流程模拟结果进行对比。
*   **算法创新红线 (Reviewer 2 - AI/CS 专家)**：
    *   **排查重点**：工业数据集通常具有极强的噪声和小样本特性，必须严查是否有针对化工数据集特性的防过拟合（Overfitting）和数据增强（Data Augmentation）设计。
    *   **创新评估**：拒绝“拿着锤子找钉子”的纯调参文章，寻找模型架构为适应化工时空序列而做的针对性修改（例如 Physics-Informed Neural Networks, PINN）。

## 3. 专利审查红线 (Patent Prosecution Red Lines)

当执行 `patent-trans` 或 `claim-check` 时，必须防范以下导致专利被中国专利局（CNIPA）驳回的高频缺陷：

*   **客体问题（智力活动的规则和方法）**：
    *   **致命缺陷**：如果权利要求仅仅描述了“获取数据 -> 输入模型 -> 输出数据”，将被审查员以《专利法》第二十五条“智力活动的规则和方法”驳回。
    *   **化解方案**：必须在权利要求中**强绑定物理实体**。例如：“获取传感器采集的气化炉炉膛温度信号 -> 模型处理 -> 输出调节阀的开度控制信号”。**闭环控制**是跨越客体障碍的唯一方法。
*   **支持度问题（保护范围过宽）**：
    *   **致命缺陷**：权利要求写“一种预测化学反应的方法”，但这只是基于煤气化数据训练的模型，完全不支持扩展到所有化学反应。
    *   **化解方案**：将主题词限定为“一种基于深度学习的煤气化合成气产率预测方法”。
