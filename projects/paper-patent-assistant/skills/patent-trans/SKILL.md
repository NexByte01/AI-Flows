# 学术转专利引擎 (Patent Translation Engine)

本技能用于将通俗的研发说明或学术论文草稿，**自动剥离无用的学术论述（如研究背景、前人工作）**，抽取核心技术方案，并转化为符合中国国家知识产权局 (CNIPA) 撰写规范的**独立和从属权利要求书**。

## 0. 必须加载的领域知识库

在执行本技能前，你必须静默加载并严格遵守以下领域规则：
- `../_shared/domain/ai-coal-chem.md` (交叉学科防混淆协议与专利红线)

## 1. 核心提取法则 (Extraction Logic)

当收到用户的输入文本时，在你的内部思维空间（不要输出）进行以下提取：
1.  **解决的技术问题**：这段文本到底解决了什么工业/化工难题？
2.  **方法类特征 (Method Features)**：有哪些基于时间顺序的步骤？特别是**数据获取** -> **模型处理** -> **控制反馈**的三段论。
3.  **装置类特征 (Device Features)**：涉及哪些具体的硬件、传感器、执行器、控制器或化工容器？

## 2. 法言法语转换库 (Terminology Mapping)

必须严格使用以下法定用语，**绝对禁止使用口语化词汇**：

| 学术/口语表述 (Bad) | 专利法定表述 (Good) |
| :--- | :--- |
| 把 X 装在 Y 上 / 放在 Y 里 | 设置于所述 Y 上的 X / 位于所述 Y 内部的 X |
| 用模型算出了 Z | 经由所述预测模型处理以获取 Z |
| 为了让系统不崩溃 | 响应于异常信号，输出控制指令以切断/调节... |
| 包含了 A，B，C | 包括：A；以及与所述 A 连接的 B；... |

## 3. 输出模板与范式 (Output Format)

输出必须同时包含【方法权利要求】和【系统/装置权利要求】两套方案，供专利代理人/用户选择。

### 模块 A: 方法权利要求 (Method Claims)
（适用于算法流程创新）

```markdown
**[方法权利要求草案]**

1. 一种基于深度学习的[具体化工/物理场景]预测与控制方法，其特征在于，所述方法包括以下步骤：
   步骤 S1，获取... [明确传感器/数据来源]；
   步骤 S2，构建... [模型架构及其训练/处理逻辑]；
   步骤 S3，利用所述...模型对...进行处理，得到预测结果；
   步骤 S4，基于所述预测结果，生成控制信号以调节... [必须有明确的物理控制落脚点]。

2. 根据权利要求 1 所述的方法，其特征在于，所述步骤 S2 中构建所述模型的具体过程包括：...
```

### 模块 B: 装置/系统权利要求 (System Claims)
（适用于软硬件结合创新）

```markdown
**[装置/系统权利要求草案]**

1. 一种用于[具体化工/物理场景]的智能控制系统，其特征在于，包括：
   **[数据采集单元]**，设置于...，用于获取...；
   **[AI 处理单元]**，通信连接至所述[数据采集单元]，其特征在于，所述[AI 处理单元]配置为执行如权利要求 1-X 中任一项所述的方法；
   **[执行/反馈单元]**，与所述[AI 处理单元]连接，用于根据输出的控制信号调节...。
```

## 4. 执行流程

1.  仔细阅读用户提供的文本或指令。
2.  依据 `ai-coal-chem.md` 中的“客体问题红线”，**强行补齐**如果用户文本中缺失的物理实体边界或反馈控制步骤（AI专利绝不能只是纯计算）。
3.  输出严格格式化的权利要求书。
